Learned image compression

Your photograph, stored as text.

A convolutional network crushes a picture down to a small grid of whole numbers. A second network learns exactly what those numbers cost in bits, packs them at the theoretical limit, and writes the result into a JSON file. A third network reads that file and rebuilds the photograph.

Nothing about the transform is hand designed. It was trained against a loss that counts the output file size in bits, so it learned what to keep and what to throw away by being scored on the answer.

There are two modes. Lossy uses that network and reaches about 60x, by deciding what to throw away. Lossless throws away nothing at all: no network, just prediction and exact arithmetic, and the picture returns bit for bit.

The pipeline

What actually happens

Six steps, in the order they run. The interesting one is step four, and it is the step most explanations skip.

01

Images are numbers

A 4K photo is 3840 by 2160 by 3, about 25 MB of raw bytes. Neighbouring pixels are nearly always similar, so most of those bytes repeat something you already know.

02

Strided convolutions squeeze it

A convolution slides a small window across the image. Give it a stride of two and it hops two pixels at a time, halving each dimension. Four in a row take 3840 by 2160 down to a 240 by 135 grid.

03

Quantisation

The grid is rounded to whole numbers. This is the lossy step and where most of the saving comes from. Rounding has no gradient, so during training we add uniform noise instead as a smooth stand in.

04

The entropy model counts bits

A second network learns how values are distributed in each channel. Knowing a value's probability tells you its exact cost, which is minus log two of p. Common values cost a fraction of a bit.

05

rANS packs the bits

A range coder writes the symbol stream at essentially the theoretical limit, measured here at within 1.6 percent of Shannon entropy. This is where the ratio actually comes from.

06

JSON

The bitstream is armoured into base85 text and dropped into a readable header. Your original filename rides along inside, so decoding hands the picture back under the name it went in with.

The trick

The loss function is the whole idea

Two terms, fighting each other, both differentiable. 

loss = lambda × distortion + rate

Rate is real bits, straight out of the entropy model in step four. Distortion is how wrong the rebuilt picture is. Because the rate term is differentiable, backpropagation can push the encoder toward pictures that are cheap to write down and still sufficient to rebuild. Without a learned entropy model you are just saving an array and hoping a generic compressor does well on it afterwards.

Lambda is the quality knob, and it is the only difference between a 200 KB model and a 2 MB one. One model per quality level, which is why the compressor has a model picker rather than a slider.

Three things worth being straight about

The weights are part of the format

The decoder cannot rebuild anything without the exact weights that encoded it, which is why every file carries a fingerprint and decoding refuses on a mismatch. The checkpoint is a shared codebook, like the tables baked into every JPEG decoder. Send someone a file and not the model, and they get nothing.

This is compression, not encryption

The payload looks unreadable, but there is no key and no secret. Anyone holding the checkpoint can read it. Do not use this to hide anything. If you want secrecy, encrypt the file afterwards. The two are separate jobs and mixing them makes both worse.

JSON costs 25 percent

Text can only carry about 6.1 bits per character in base85, so the file is a quarter larger than the raw bitstream. That is the price of the container being JSON, not a flaw in the codec. Both numbers are always shown so you can see the tax.

The other mode

Lossless, when nothing may be discarded

The network above earns its ratio by dropping detail. Sometimes that is not acceptable, and then the job stops being about learning and becomes pure prediction: guess each pixel from the ones already decoded, and write down only where the guess was wrong.

01

Reversible colour

YCoCg-R decorrelates red, green and blue using only integer adds and shifts, so it inverts exactly. Worth about 1.7 MB on a 3 megapixel photograph before anything else happens.

02

Predict, then code the error

The median edge predictor from JPEG-LS guesses each pixel from its left, up and up-left neighbours, switching behaviour at edges. Good guesses make small numbers, and small numbers cost few bits.

03

Decoded on the diagonal

Each pixel needs its neighbours rebuilt first, which sounds strictly sequential. But the predictor only looks left and up, so a whole anti-diagonal resolves at once: 3,575 steps instead of 3.1 million.

Measured on held out photographs the bitstream lands about 20 percent under PNG, bit for bit identical, and the server checks that claim on every single request rather than trusting it. Two honest caveats: wrapping it in JSON costs 25 percent, which cancels the win almost exactly, so as a file it sits level with PNG. And PNG wins on synthetic patterns, because zlib finds exact repeats and this coder has no match model at all. It is built for photographs.
